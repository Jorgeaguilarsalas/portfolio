## 1. Context

Jorge reported two nav bugs on jorgeag.com:

1. The nav header sits at a different distance from the top on different pages.
2. On some pages the nav does not stay fixed while scrolling.

Scope: the 37 portfolio pages in this repo, in EN/DE/ES. Excluded: `/motion/` (separate repo), `/343ride-landing.html` (separate brand), and `/cv/`, which has no nav and is not deployed (`cv/` is in `.assetsignore`, so the live site returns 404).

## 2. Diagnóstico

Method: headless Chrome (puppeteer-core 24.10.0 driving the local Chrome), all 37 pages at 1440×900 and at 390×844 (mobile emulation). The cookie banner was suppressed by a stored decision, and Umami/GA by `?noga` in localStorage. For each page the script measured the nav's computed `position`/`top`/padding, its height and its offset from the top at load, body margin and padding, ancestors with non-visible `overflow`, and the nav's position after scrolling down and then back up 300px.

### Root cause(s) identified:
- **`/contact/`, `/de/contact/`, `/es/contact/` had their own nav that never got the shared nav styles.** Their CSS lives in `/contact/form.css` instead of inline, and that file had a separate, simpler nav block: padding on `.nav-inner` instead of `.nav`, `flex-wrap:wrap`, no styling for `.nav-pagelink` (the links rendered as default underlined links), and no hamburger or mobile menu.
  - Desktop: nav 77px tall instead of 85px, brand 16px from the top instead of 20px. This is the "different distance from the top".
  - Mobile: the links, language switch and CV button wrapped onto three lines, making the nav **199px** tall instead of 73px. When `/nav.js` hid it on scroll, it slid away as a 199px block, which reads as "not fixed".
- **The 404 pages (×3) had no `position: sticky` at all.** Their `.nav` is static. The page is only one screen tall so it barely shows, but it is the only nav on the site that is not sticky.

### Audit results:
- `position` property across pages: `sticky` on 34/37. `static` on `/404.html`, `/de/404.html`, `/es/404.html`. No page uses `fixed`.
- `top:` values: `0px` on every sticky nav. No per-page overrides, and no case where the nav starts below the top (offset at load = 0 on all 37 pages, both viewports).
- `padding-top`: `.nav` has 20px 32px on desktop and 14px 20px at ≤800px on 34/37 pages. The 3 contact pages had 0 on `.nav` (the padding was on `.nav-inner`, 16px). Body `margin-top` and `padding-top` are 0 on every page, so nothing pushes the nav down.
- `/nav.js` loading: loaded on all 37 pages, `defer`, in `<head>`. Not on `/cv/`, which has no nav. The auto-hide logic in `nav.js` is the same everywhere and worked on every page where it could run.
- `overflow:` ancestors: the nav is a direct child of `<body>` on every page. 31 pages have `body{overflow-x:hidden}` (computed `hidden/auto`). Because `<html>` stays `visible`, the browser applies body's overflow to the viewport instead, so body does not become a scroll container and sticky is not broken. Confirmed: on all of those pages the nav stayed pinned (top 0) after scrolling 2,200px. Contact and 404 have no overflow ancestors.

### Pages affected:
- `/contact/`, `/de/contact/`, `/es/contact/`: wrong height and padding on desktop, three-line nav on mobile.
- `/404.html`, `/de/404.html`, `/es/404.html`: nav not sticky.

### Pages NOT affected (preserved):
- Home (`/`, `/de/`, `/es/`), `/about/` ×3, `/work/` ×3, `/leadership-framework/` ×3, case studies (`/wolt/`, `/bolt/`, `/bliq/`, `/nexio/`, `/alcorte/`) ×3, `/impressum/`, `/datenschutz/`, `/privacy/`, `/es/privacidad/`. All were sticky with `top:0`, 85px on desktop and 73px on mobile, and hid and reappeared correctly. Not modified.

## 5. Decisions

- **Copied the case-study nav to contact rather than inventing a third version.** The case-study nav already serves 25 pages (case studies, work, framework, legal) with the same back link and page links as contact. Contact's markup was already that nav minus the hamburger, so copying it was the smallest change that gives the same result.
- **No "Get in touch" CTA in the contact nav or menu.** It would link to the page you are already on. The old contact nav didn't have one either.
- **404 keeps its minimal nav** (brand + language switch, no hamburger). It now only gains sticky. On mobile it stays 81px because the language switch sits in the bar and grows to 44px touch targets on touch screens (`pointer:coarse`). Making it 73px would mean shrinking the touch targets below 44px or adding a menu to a one-screen error page.
- **`body{overflow-x:hidden}` was left alone.** It does not break sticky here (measured), and removing it could bring back horizontal scroll on pages with wide content.

## 6. Deviations from spec

- **No `--nav-top` CSS variable.** The brief suggested it as a typical fix if `top:` was inconsistent. The audit found `top:0` on every page and no overrides, so a token would change nothing. Centralizing the nav CSS properly is a larger refactor (see §7).
- **`.reports/` added to `.assetsignore`.** The brief asked for the report in the repo for WebFetch via raw.githubusercontent.com. That works (the repo is public). But with `directory="./"` in Wrangler, the same file would also be published at `jorgeag.com/.reports/…`. Excluded, the same way `.claude/` is.
- **Screenshots are committed to the repo** (≈400 KB) instead of left in the local scratchpad, because the chat session reading this report has no access to the local machine.
- **`/cv/` was not audited for nav:** it has no nav and is not deployed.
- **Safari not tested** (no WebKit available in this environment).
